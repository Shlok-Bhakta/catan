# Production adversarial playtest — September 29, 2026

Ten `gpt-6-luna` reviewers tested the public Convex API and browser in waves of up to three simultaneous reviewers. Some shared a room and took separate seats; others drove three-seat or eight-seat rooms independently. Reviewers logged sanitized actions and before/after game state under `/tmp/catan-chaos-*` and `/tmp/catan-reviewer*.jsonl`. Session tokens stayed in private files and are not in this repository.

The confirmed failures and timing artifacts are summarized in [the error log](playtests/2026-09-29-errors.jsonl). The three-reviewer post-fix room also wrote sanitized logs under `/tmp/catan-postfix-ZB8MFL/`.

## Confirmed failures

| Area | Production evidence | Fix |
| --- | --- | --- |
| Session ownership | In `MNLTGC`, `games.join` accepted an empty token. Querying and acting with that token controlled the new seat. | `join` rejects tokens shorter than 20 characters. Seat lookup also ignores them, including seats created before the fix. A live post-deploy probe returned `ConvexError.data = "Invalid session."`; querying with the empty token returned only the join view. |
| Board input | In `5UA5LA`, a setup action with `vertex: null` applied and placed a settlement at vertex 0. | Board actions require an actual integer index. A regression test covers null and string indices. |
| Expected rule errors | Out-of-turn actions, invalid placements, and bad trades returned only `Server Error` in production, although state stayed unchanged. | Rule failures use `ConvexError` and the browser displays its safe `data` message. A live post-deploy out-of-turn probe returned `"Wait for your turn."` in `data`. |
| Player trades | In `4E6T98`, a nonactive player's valid counteroffer to the active player was rejected. In the same room, a grain-for-grain offer applied and appeared in the offers list. | Nonactive players may offer only to the active player, who may accept. Offers with a resource on both sides are rejected. The browser exposes counteroffers and preserves the form after a failed offer. |
| Supply shortage | Source audit against the [2025 official rulebook](https://www.catan.com/sites/default/files/2025-03/CN3081%20CATAN%E2%80%93The%20Game%20Rulebook%20secure%20%281%29.pdf) found that the engine withheld all of a scarce resource even when only one player was owed it. It also evaluated shortages one hex at a time. | Production claims are now grouped by resource across all rolled hexes. The sole claimant receives the remaining cards; multiple claimants receive none if supply is short. Covered by a focused test. |
| Longest Road ties | Source audit found that the engine assigned the award to the first sorted player after the holder's route broke, even when two players tied. | The award returns to the supply on a tied lead after a break and transfers only to a unique leader. The current holder keeps it when another player merely ties an unbroken route. Covered by two focused tests. |

## Paths that held

- Shared three-seat play verified setup, normal turns, development purchases, Largest Army at three Knights, seven, discard, robber, steal, action-ID replay, and stale clock rejection.
- Placement probes rejected duplicate or adjacent settlements, disconnected setup roads, and a road that tried to pass through an opponent's settlement. Rejected actions left state unchanged.
- The eight-seat room completed all 16 setup placements. Five normal turns ended clockwise. Out-of-turn actions did not change state; duplicate action IDs applied once; private queries concealed other players' hands.
- An eight-seat `end` later returned `stale`. Its runner failed to preserve the room code and post-response snapshot, so this result is inconclusive. The room was located through a restricted internal playtest query and deleted.
- In the post-fix shared room, three reviewers confirmed that invalid board indices and trades returned specific `ConvexError.data` messages without attributable state changes. A timeout after a seven completed two required discards, moved the robber, and advanced the turn. No internal server error with missing `data` was observed.
- A counteroffer from a nonactive player appeared in the browser's offer list. The reviewers twice missed the 60-second acceptance window. A targeted live probe then offered 1 grain for 1 wool, accepted it from the active seat, verified the exact one-card exchange in both private views, and confirmed the offer cleared.
- A Playwright probe in the active seat clicked an underfunded bank trade in the deployed UI. Its alert read `Trade unavailable.` and the page had no console error.

## Service pressure

Several production API calls took 10–18 seconds while test rooms ran in parallel. Kiwi's Catan containers were healthy and its hard drive had free space. A one-second disk sample reached 94% utilization with about 173 ms average write wait; a separate ClickHouse container on the same drive showed sustained write activity. This is a measured latency risk for a 60-second turn, not a confirmed game-state failure.

## Verification

The post-fix rule suite passes 20 tests and the production build succeeds. All ten test rooms were deleted; public queries returned `null` for every code.
